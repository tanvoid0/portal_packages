The Flutter layer under the Portal apps.

Seven packages, extracted rather than designed: an AI assistant runtime that finds whatever model is nearby, an offline-first platform layer, a token-driven design system, and the small things every app ends up needing.

Flutter ≥ 3.0 Dart ≥ 3.8 Android · iOS MIT

Install

flutter pub add portal_ui_core portal_ai

Each package stands alone — take the ones you need. portal_platform pulls in portal_crypto and portal_ui_core.

Use

Theme an app from tokens, then compose from the kit.

import 'package:portal_ui_core/portal_ui_core.dart';

MaterialApp(
  theme: buildPortalTheme(brightness: Brightness.light),
  darkTheme: buildPortalTheme(brightness: Brightness.dark),
);

// in a widget
final tokens = PortalUiTheme.of(context).tokens;
PortalCard(
  child: PortalStatCard(value: '12.4k', label: 'Steps'),
);

Give the assistant your tools; it picks the backend. post is optional — without it the runtime uses the device's own model, an Ollama on the LAN, or the user's key.

import 'package:portal_ai/portal_ai.dart';

final ai = PortalAiRuntime.create(
  post: apiClient.post,
  env: dotenv.env,
  feature: 'gym-assistant',
  appDescription: 'Workouts, routines and exercise logs.',
  tools: gymAiTools(),
);

final result = await ai.ask(
  'How did my week go?',
  onReply: (delta) => stdout.write(delta),
);

What it looks like

Both are the packages' own example/ apps. No backend behind the assistant — the conversation is canned.

Bring a server, or don't

Nothing in portal_ai needs a backend: on-device Gemini Nano, a LAN Ollama and a user-supplied key all run from the app. Hand it a post callback and cloud requests go through your API instead, which is where the key, the model choice and the per-user quota belong in production. The contract is two routes, and llmwire — same author, zero-dependency TypeScript client for every major provider — serves them in a few lines each.

POST /ai/complete
  { systemPrompt, prompt, jsonMode, temperature, feature }
  → { text, model?, usage? }

POST /ai/complete/stream            server-sent events
  data: {"text":"delta"} … data: [DONE]
import { aiFactory } from 'llmwire';

app.post('/ai/complete', async (req, res) => {
  const out = await aiFactory.process(req.body);
  res.json({ text: out.data, model: out.modelUsed,
             usage: out.usage });
});

Full contract and the streaming route in the portal_ai README.

Packages

portal_ai

Backend discovery — Gemini Nano on-device, Ollama on the LAN, a cloud key, or your server — plus a shared chat runtime, tool calling, proposals and the assistant UI.

portal_platform

Auth, session, API client, config, deep links, in-app updates, Sentry, and an offline-first sync layer with a replayed mutation queue. Opinionated, GetX-based.

portal_ui_core
