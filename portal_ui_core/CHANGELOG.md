## Unreleased

- Visual sweep fixes (docs/ui-kit/notes/visual-sweep-2026-10-25.md in the app repo):
  - `portalOffPage(context, fill)` (new): a neutral fill within 1.05:1 of the page
    behind it steps 6% toward `onSurface`. Applied to the secondary / icon
    `PortalButton`, the grouped `PortalStepper`, the neutral `PortalPrompt`, the
    default `PortalProgress` track, the neutral `PortalBadge`, `PortalTextField`,
    `PortalSelect` and `PortalComposer`, so they no longer vanish on a grouped
    light page or where a skin folds surface tones together.
  - `portalInkOn(fill, preferred)` (new). `PortalFilterChip.selectedColor` /
    `PortalSegmentedTabs.accentColor` with no on-colour now pick a readable ink.
  - `PortalFilterChip`: a selected chip with no glyph of its own draws a check
    (not action, menu or input chips). **Visual change**, selected chips get wider.
  - `PortalButton`: `onPressed == null` (and not loading) dims like a disabled row;
    `expand` no longer strands the icon from its label.
  - Switch: selected track is solid primary (was 55% alpha, read as disabled); a
    disabled track is onSurface 12%.
  - Material filled / elevated / outlined / text button labels and `PortalPrompt`
    actions carry the app typeface; `PortalSelect` value and hint too.
  - `PortalFeatureCard` eyebrow kept readable on its wash; `PortalStartupSplash`
    failure centres; `PortalChevronLink` ellipsizes; `PortalChoiceGrid` never
    makes more columns than choices; `PortalStepper` value uses `onSurface`;
    `PortalListItem` centres short rows' content.
- `PortalSegmentedTabs`: new `style` (`PortalSegmentedTabsStyle.solid`, the
  default, or `.tinted`). Solid marks the selected segment with a solid fill and
  on-colour text and outlines the rest -- the selected state of
  `PortalFilterChip`, and re-skinned by the same `PortalFilterChipTheme`, so an
  app sets its selected colour once for chips and segmented controls alike.
  **Visual change:** the old soft-tint look is now `style: .tinted`.
- `PortalFilterChipRow`: fades whichever end of the strip still has chips past
  it (nothing while they all fit), so a chip clipped by the viewport reads as
  scrollable instead of as the last one.
- `PortalOnboardingPage`: optional `busy` (default false) and `busyLabel`. When
  `busy` is true the sign-in button shows an in-button spinner and refuses taps
  (wired to `PortalButton.isLoading`/`busyLabel`), so a connect flow can guard a
  double-tap / duplicate OAuth without faking it through the label. Default
  false is unchanged, today's behaviour.

- Icon system: Material Symbols, one voice (new dep `material_symbols_icons`, re-exported as `Symbols`; `PortalIcons` is a typedef of the same class so the fleet's icon set has a Portal name). Every glyph is `Symbols.<name>_rounded` — the rounded style only, so the outlined and sharp fonts tree-shake to ~2 KB each in a release build — and the axes live in the theme, not at call sites: `buildPortalTheme` sets `IconThemeData(fill: 0, weight: 400, grade: 0, opticalSize: 24)` on `iconTheme` (Material's default colours) and `primaryIconTheme` (`onPrimary`), and `applyPortalComponentThemes` now recolours those with `copyWith` instead of replacing them, so the axes survive the config path (test pins both). Selection is `fill` 0 → 1 on the *same* glyph, animated on `tokens.motion.standard`: `PortalBottomNavBar` fills the selected destination over `tokens.motion.medium` (`PortalNavDestination.selectedIcon` is now optional — it stays for the apps' remaining `Icons.x_outlined`/`Icons.x` pairs, and the fill runs alongside a swap) and `PortalFilterChip` fills its `icon` over `tokens.motion.fast`, in step with its own colour change. `PortalSegmentedTabs` has no icon slot, so nothing to fill there. ui_core's own glyphs (`PortalSearchField`, the app bar overflow, the startup splash, the toast host) migrated — `Symbols` has no `_outline` names; unfilled *is* outline. Measured on the example gallery, `flutter build apk --release`: 51,275,684 → 51,341,427 bytes (+64 KB) for its 26 glyphs — the rounded font shrinks 15.07 MB → 60 KB, so tree-shaking holds and the sed-to-`Icons.x_rounded` fallback is not needed. The axes only reach a `ThemeData` built by `buildPortalTheme`/`PortalThemeConfig`: an app that hand-rolls `ThemeData(iconTheme: IconThemeData(color:, size:))` gets Flutter's `IconThemeData.fallback()` for the missing axes, i.e. opsz 48, and ui_core's Symbols glyphs render thinner there — move onto the factory before or with the app's Symbols sweep. Both fill tweens clamp to `[0, 1]` (a spring `motion.standard` may overshoot; `Icon` asserts the range) and drop to `Duration.zero` under reduce-motion, as does the nav bar's well.

- `PortalFab(icon:, tooltip:, onPressed:)` / `PortalFab.extended(icon:, label:, onPressed:, tooltip:, scrollController:)` and `PortalToolbar(actions:, clearance:)`. The FAB is the theme's `floatingActionButtonTheme` (colour, corner) drawn through `PortalPressable` — scale under the finger, spring back, Material's ripple kept on top — with one `PortalHaptics.medium()` on tap, and flat by decision like the toolbar and glass header: `floatingActionButtonTheme.elevation` is ignored (a press-scaled shadow can only live inside `PortalPressable`'s own `Material`), so apps drop their FAB `elevation:` in the D sweeps. The icon is pinned to 24 dp like Material's FAB so the box is 56 square under the 22 dp fleet icon theme too. The extended form collapses to the 56 dp icon while the page scrolls down and re-extends on a scroll up or on reaching the top by any route — drag, `animateTo`, `jumpTo` (`AnimatedSize` on `tokens.motion.standard`, instant under reduce-motion), following `scrollController` or the route's `PrimaryScrollController` — which a `PortalScrollPage` body attaches to on Android/iOS, so inside one it needs no wiring there (desktop passes `scrollController`); every tab of an `IndexedStack` shell shares that controller, so a position under the finger is read by direction and an idle one only when its offset moved to the top. `tooltip` is required on the icon-only form and defaults to `label` on the extended one, excluded from semantics while the label is visible. No `Hero`: B2's shared-axis transition makes a FAB flight noise and two FABs on a screen stop colliding on a tag. The toolbar is M3 Expressive's floating pill of icon actions — `PortalAction`s drawn by `PortalActionButton`, the app bar's inline icon button (formerly private), so `tooltip` and badge come for free — as glass on every visual theme like the collapsed `PortalHeader`: `portal.card` at `PortalGlassStyle.tintAlpha` over a `blurSigma` backdrop blur, the theme hairline as its edge, no shadow (a translucent fill over a shadow's own fill only reads as a darker pill). `clearance` (default `PortalBottomNavBar.overlayClearance`) is the room kept under it for a nav that floats over the body; 0 when the `Scaffold` owns the nav. Sit it in `floatingActionButton` with `centerFloat`.

- `PortalAvatarMark(initials:, image:, size:, statusColor:)`, `PortalCountBadge(child:, count:, visible:, backgroundColor:, foregroundColor:)` and `PortalProgressRing(value:, size:, strokeWidth:, label:, color:)`. The avatar is Material's `CircleAvatar` on `primaryContainer` — the photo in `foregroundImage` so a 404 or offline degrades to the initials, two characters upper-cased in the type style that fits the step — at the new `DesignTokens.avatarSizes` (`PortalAvatarMarkSize.sm` 32 / `md` 40 / `lg` 56 — not `PortalAvatarSize`, which the `portal_avatar` brick seeds into apps), with an optional status ring in a semantic colour drawn *inside* the token size so a row of avatars stays aligned. It is named `PortalAvatarMark`, not the spec's `PortalAvatar`, because `portal_platform` already exports a public `PortalAvatar(user:)` and gym uses it in files that import both packages; that one keeps its name and its session lookup, and can draw with this in the D batch. The badge is Material's `Badge`/`Badge.count` (offset, 6 dp dot, 16 dp pill, `999+`) plus what every call site wrote by hand: `count: 0` hides, `count: null` is a dot, and `backgroundColor`/`foregroundColor` take a semantic pair (`s.success`/`s.onSuccess`) — theme `error`/`onError` when null. It is `PortalCountBadge`, not `PortalBadge`, because the `portal_badge` brick seeds a label chip by that name (gym has one) and the barrel would make it ambiguous. The ring is `CircularProgressIndicator` with a round cap and the theme's track, springing to each new value on `tokens.motion.standard` over `tokens.motion.medium` (from empty on first build; jumps under reduce-motion), clamped to 0..1 so a full ring never wraps, with the animated percentage in tabular figures in the centre (or your own `label`), in a `FittedBox` that only shrinks so a large text scale stays inside the arc — excluded from semantics because the indicator announces it. Diameter defaults to `avatarSizes.lg`, stroke to `spacing.xs`.

- `PortalRefresh(onRefresh:, child:, edgeOffset:)`: the fleet's pull-to-refresh over `RefreshIndicator`, for the 35 default-look spinner discs in the apps. Flat (`elevation` 0) on `surfaceContainerHigh`, `primary` arc at a 2.5 stroke, one `PortalHaptics.light()` the moment the pull is released past the threshold. `edgeOffset` is where the disc drops out from — `PortalRefresh.belowBar(context, large:)` is the status bar plus a pinned `PortalSliverAppBar`, or plus the expanded `PortalHeader.large` (now `PortalHeader.expandedHeight`, 152, passed to the sliver explicitly rather than left to Material's private default) — so the disc appears under the bar instead of over it. `PortalScrollPage(onRefresh:)` uses it and picks the offset from its own bar: 0 with none, the compact offset for its default bar or a custom `appBar:`, the large one for `header:`.

- `PortalHeader.large(title:, subtitle:, actions:, trailing:)` and `PortalScrollPage(header:)`: the fleet's large-title header over `SliverAppBar.large`, for the 11 hand-rolled `SliverAppBar`s in the apps. Material owns the collapse and the cross-fade; the header puts `textStyles.headline` on the expanded title (`body` on the subtitle under it) and collapses into the compact bar's own title — the same `_PortalAppBarTitle` `PortalAppBar` draws — so a large-title page scrolls into exactly the bar its siblings wear, actions overflow into the same sheet. The collapsed bar is the one glass surface on every visual theme: the theme's bar colour at `PortalGlassStyle.tintAlpha` over a `blurSigma` backdrop blur (a private sliver `BackdropFilter`, clipped to the bar — Flutter has no sliver one), `scrolledUnderElevation` 0. `header:` on `PortalScrollPage` carries its own title and actions, so the page's `title`/`actions`/`trailing` are ignored beside it; `appBar:` still wins for a hand-dressed sliver.

- `PortalSwipeRow(key:, child:, leading:, trailing:, borderRadius:)`: the fleet's swipe-to-act row over `Dismissible`, for the hand-styled `Dismissible`s in the apps. Each side takes a `PortalSwipeAction(icon:, label:, foregroundColor:, onTrigger:, confirm:, dismisses:)`; the revealed background is the action's colour at 18% with its icon and label in the colour, the icon grows from 0.7× as the finger nears the 40% threshold and pops to 1.2× on `spatialFast` — with one `PortalHaptics.medium()` — the moment it is crossed. `confirm` (`() => portalConfirm(context, …)`) is asked after the slide-out and false springs the row back; `dismisses: false` is a toggle (complete, pin) that fires `onTrigger` and settles back instead of leaving the list. Both actions are exposed as custom semantics actions, so a screen reader triggers them without the gesture; the background is `ExcludeSemantics` so its label does not merge into the row's. The gesture, fling and slide-out are Material's, which means the row's own settle after a release is `Dismissible`'s linear `movementDuration` (`tokens.motion.fast`), not a spring — the spring is on the icon.

- `PortalSheet.show<T>(context, builder:, title:, detents:, isScrollControlled:, showGrabber:, isDismissible:)`: the fleet's modal bottom sheet over `showModalBottomSheet`, replacing the per-call restyling at 36 sites. Surface, `radii.xl` top and grabber styling come from B4's `bottomSheetTheme`; the sheet passes `showDragHandle` (default on — hidden when `isDismissible: false`, since Material gives the handle its own drag-to-close), `useSafeArea` for the status bar, and wraps the content in `SafeArea(top: false)` plus the keyboard's `viewInsets` so the surface still runs under the nav bar. `isScrollControlled` defaults to true (a `mainAxisSize: min` body stays short; the keyboard lifts the sheet instead of squashing it inside the 9/16 cap). It slides on `tokens.motion.emphasized` (the spatial spring; its 1.5% overshoot lifts the bottom edge a few px off the screen for a couple of frames — the trade for the spring) at `tokens.motion.medium`, leaves on `standard.flipped` like B2's pop, and skips the animation under reduce-motion. `detents: [0.45, 0.9]` puts a `DraggableScrollableSheet` inside (fractions of the height under the grabber and above the keyboard, snapping between them, `PrimaryScrollController` carrying the sheet's controller to the body); the smallest detent rests rather than closes — the grabber, barrier and back dismiss — because Material closes on *reaching* the minimum, which would make a two-detent sheet dismiss whenever it collapsed. `title:` wraps the body in the scaffold, letting a `ScrollView` body scroll itself. `PortalSheetScaffold(title:, body:, actions:, scrollable:)` is the title + scrolling body + pinned action row most sheets hand-build, all on the page gutter; the body scrolls in a `SingleChildScrollView` on the primary controller unless `scrollable: false` hands that to a `ListView` of its own.

- Remaining sub-themes off Material defaults, on the `PortalThemeConfig` path (`buildPortalTheme` alone still leaves them at M3; the example gallery now builds through the config so it shows them). `datePickerTheme` and `timePickerTheme` sit on the dialog's shell — `surfaceContainerHigh` (a surface palette's `cardColor` still wins), `radii.xl`, hairline, elevation 0 — with the time picker's dial and unselected hour/minute field at the input fill (M3's default Highest folds into a surface palette's panel) and `radii.md`. `bottomSheetTheme` keeps `radii.xl` top on the panel surface and styles the drag handle without forcing it on: apps still hand-draw one on transparent sheets, and C1's `PortalSheet` passes `showDragHandle` itself. `tabBarTheme` drops the divider line and sets `onSurface` selected / `onSurfaceVariant` unselected; the indicator stays M3's 3dp rounded label-width bar so `TabBar.indicatorColor` and `TabBar.secondary` keep working. `sliderTheme` is M3's 2024 slider spelled out for `Slider` and `RangeSlider`, since `year2023: false` is deprecated: a 4×44 pill handle that narrows under the finger (`HandleThumbShape`), a 16dp track with a 6dp gap either side of it (`GappedSliderTrackShape`), 2dp tick marks, and a rounded-rect value label; the inactive track is `primary` at 15% like the progress track, because a surface palette maps `secondaryContainer` a hair off the card.

- Dynamic colour seam, opt in. `PortalThemeConfig.dynamicColor` (default false) and `PortalDynamicColorBuilder(config:, builder:)`, which hands the builder `PortalThemeModes` — a plain `config.build()` while the flag is off; with it on, the widget asks the `dynamic_color` plugin (new dep) for the device's Material You scheme — owning the query itself rather than wrapping `DynamicColorBuilder`, so the flag can flip at runtime without remounting the app under it — and `PortalThemeConfig.build(wallpaper:)` harmonises the brand seed toward its primary (`Blend.harmonize`: hue rotated up to 15°, chroma and tone kept) rather than replacing it, so the app nods to the wallpaper and stays on brand; the semantic roles derive from the harmonised primary and follow. First frame and any device without dynamic colour are the brand palette. No app turns it on.

- Page transitions by default: `buildPortalTheme` sets `pageTransitionsTheme` to a `PortalPageTransitionsBuilder` on every platform — the horizontal shared-axis slide `PortalPageTransitions.sharedAxis` already drew, on the `effects` spring at `tokens.motion.medium` — so a plain `MaterialPageRoute` moves the Portal way with no call-site change. `PortalPageTransitions.fadeThrough` stays the call-site route for a root destination (the theme is per platform, not per route). `PortalHero(tag:, child:, borderRadius:)` wraps `Hero` with a shuttle that clips the flight to a radius lerped from the departing end's corners to the arriving end's, so a card no longer snaps square the frame it lifts off; `PortalCard(heroTag:)` opts a card in with its own radius.

- Tonal cards, larger radii, squircle on. `PortalRadii` defaults step up to sm 8 / md 12 / lg 20 / xl 28 (`rounded` to 10/16/24/32 so it still means rounder than default) and `DesignTokens.expressiveCorners` is on, so cards are continuous-corner squircles unless a token bundle says otherwise. `PortalRadiiUtils.continuousBorder` doubles the radius it is handed: Flutter's continuous corner puts its apex at r/8 against a circle's 0.29r, so at face value the squircle read tighter than the rounded rect it replaced. Glass and hero cards still clip to circular corners. The card theme is a tone on the page — `surfaceContainerLow` (dark: `surfaceContainerHigh`), no border, a surface palette's `cardColor` still wins — and `PortalCard` gets `variant: tonal` as its default beside `outlined` (the old bordered look), `elevated` (surface plus the `card` shadow, now painted outside the clipping `Material` so it actually shows) and `glass`; `standard` stays as an alias of `outlined` (deprecation waits for the app migration so `flutter analyze` stays green there). Filled buttons are pills (`PortalButton` primary/destructive and the `FilledButton`/`ElevatedButton` themes at `radii.full`), tonal/outlined/ghost keep `radii.md`. Dialogs, sheets and popups sit at `surfaceContainerHigh`, one tone above a card. Inputs fill `surfaceContainerHighest` at `radii.md` with no border until focus or error; where a surface palette folds `surfaceContainerHighest` into its card colour the fill steps to `surfaceContainerHigh`, so a field never vanishes into the card, sheet or dialog that holds it.

- Type ramp: `PortalTextStyles.hero` (44/w800, tracked -1.0) above `display` for the one figure a screen is about; every style now carries a `height` on one rule (1.1 figures, 1.2 headings, 1.25 subtitle, 1.5 body, 1.4 caption/overline). `emphasized(style)` is one weight heavier and 0.2 tighter, `numeric(style)` turns on tabular figures so counters and columns of amounts stop jittering. `PortalStatCard` sets its value in `numeric(title)`, or `numeric(hero)` with `hero: true`.

- `PortalGradients` on `DesignTokens.gradients`: the three gradients the fleet draws, built from the `ColorScheme` so they follow a theme change — `surfaceSheen(scheme)` (top-left `onSurface` at 4% to nothing, layered over a surface colour), `accent(scheme)` (`primary` → `primaryContainer` at 135°) and `imageScrim(scheme)` (`scrim` at 60% rising from the bottom edge, for text over an image). `PortalCard(sheen: true)` lays the sheen over its surface behind the content, every variant. Replaces the ad-hoc `LinearGradient`s in app code, gym's `subtleGradient` first.

- `PortalSemanticColors`: the status roles `ColorScheme` lacks — `success`, `warning`, `info` (each with `on*`, `*Container`, `on*Container`) plus `danger*` mirroring `error*` so status code reads one type. Defaults per brightness from fixed hues (green 145°, amber 40°, blue 215°) on the M3 error tone recipe, rotated toward the scheme's primary with `Blend.harmonize`; `buildPortalTheme` attaches it, `PortalSemanticColors.of(context)` falls back to computed defaults when a theme was hand-rolled, and `PortalThemeConfig.extensionsBuilder` overrides per brightness (a later `PortalSemanticColors` replaces the default). Success toasts now paint `success` (was `secondary`), destructive toasts `danger`; `PortalStatCard(delta:)` paints a `+`/`-` change in `success`/`danger`.

- `PortalHaptics`: the fleet's haptic vocabulary over the stdlib `HapticFeedback` — `selection`/`light`/`medium`/`heavy` plus the compound `success` (light→medium), `warning` (medium×2) and `error` (heavy→light→light), 40 ms apart. One global switch, `PortalHaptics.enabled`, set from the new `PortalThemeConfig.haptics` (default true) when a theme is built. Wired where it earns its place: segmented tabs and bottom nav click on a selection *change*, filter chips on every tap (the chip cannot know whether the consumer toggles or ignores a re-tap), the confirm dialog's confirm is medium, success/destructive toasts play success/error as they appear, and `PortalPressable(haptic:)` plays a `PortalHapticKind` before `onTap` for anything else.

- `PortalPressable`: press state for anything tappable — shrinks to the new `PortalMotion.pressScale` token (0.97) on the effects spring while held, springs back on the spatial one. It hosts the `InkWell`, so the scale follows Material's own pressed state (a press that becomes a scroll releases) and a quick tap still plays the press out before springing back; the ripple is off unless asked for. `PortalCard(onTap:)` presses the whole surface with no ripple, `PortalButton` keeps its ripple and adds the scale (a loading button now goes through the same path and announces as disabled), `PortalFilterChip` and `PortalStatCard` press too.
